Commit progress straight to the repository

The roadmap is read from the workbook in the repository, so this page needs a connection before it can show anything. Once connected, every mark is committed back to that workbook a few seconds after you make it, and the two names in the header are saved with it.

Repository

Path from the repository root. Filled in from the page address where possible.

Access token

  1. On GitHub open Settings → Developer settings → Personal access tokens → Fine-grained tokens, then Generate new token.
  2. Under Repository access choose Only select repositories and pick this one repository.
  3. Under Permissions → Repository permissions set Contents to Read and write. Leave everything else alone.
  4. Set the shortest expiry you can live with, generate it, and paste it below.

Keeps the repository details and the token in this browser, so you connect once and not again. Switch it off on a machine you share and the token is kept for this session only.

Not connected.
Handle the token carefully.
  • It is kept in this browser only. It is never written into the workbook, the exports or the repository, and it is sent nowhere except github.com.
  • Anyone who can use this browser profile can use the token. Don't connect on a shared or public machine, and use Forget token when you are done.
  • Each person needs their own token and write access to the repository. Don't pass one around.
  • If the token ever lands in a commit, a log, a screenshot or a chat, revoke it on GitHub straight away.
  • Commits are attributed to the token's owner, so the history shows who changed what.

Progress is saved automatically.

Topics, progress and the two names all live in coveo-kt-tracker.xlsx in the repository. The page reads it once you connect on the Connection tab, and commits each change back a few seconds after you make it. Save to Excel downloads the same file if you want a copy, and editing the workbook directly in Excel works too.

If the repository is public, this page and that workbook are readable by anyone. Keep organization IDs, source IDs, endpoint URLs, key names and key values, store names and client identifiers out of both, and reference the private runbook instead.
